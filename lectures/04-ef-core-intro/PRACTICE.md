# Практическое задание: «Работа с БД, сущность Group»

Задание: Добавить в текущее приложение с лекции новую сущность «Группа» (Group) и реализовать для неё полноценный REST API с сохранением в базу данных через EF Core, используя архитектуру DI. Взаимосвязи между Студентом и Группой на данном этапе делать не нужно (это независимая таблица).

## Пошаговый план выполнения:

   1. Создать модель: В папке Models создайте класс `Group.cs` со свойствами `Id` (int), `Name` (string, например, "ИП-21") и `Description` (string, описание специальности).
   2. Обновить контекст: В классе `AppDbContext` добавьте новое свойство `public DbSet<Group> Groups => Set<Group>();`.
   3. Создать контроллер: В папке `Controllers` создайте класс `GroupsController.cs`.
   4. Внедрить DI: Через конструктор контроллера внедрите `AppDbContext`.
   5. Реализовать CRUD: Напишите асинхронные метода по аналогии со студентами (GET, POST, PUT, DELETE). PATCH на ваше усмотрение если останется время.

## ⚠️ ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ: Ошибка "no such table: Groups" и как её избежать

При выполнении самостоятельной работы вы можете столкнуться с ошибкой если уже успели создать students.db с одной таблицей Students:  
`Microsoft.Data.Sqlite.SqliteException: SQLite Error 1: 'no such table: Groups'`.

### Почему это происходит?
В первой части занятия в конструктор контроллера мы добавили строчку:
```csharp
_db.Database.EnsureCreated();
```
Этот метод работает по очень простому правилу:
1. Он проверяет, есть ли файл базы данных (`students.db`) на диске.
2. **Если файла нет** — он создаёт его и разворачивает все таблицы, которые прописаны в `AppDbContext`.
3. **Если файл ЕСТЬ** — он **ничего не делает**. Он не умеет изменять уже существующую базу данных и досоздавать туда новые таблицы.

Когда вы добавите новую модель `Group` и зарегистрируете её в `AppDbContext`, файл `students.db` у вас на компьютере **уже будет существовать** (ведь мы создали его на первой части пары). Поэтому метод `EnsureCreated()` просто пропустит шаг обновления, таблица `Groups` в файле не появится, а при попытке сделать запрос к API групп приложение упадет с ошибкой, что таблицы не существует.

### Как решить эту проблему на сегодняшнем занятии (2 способа на выбор):

#### Способ 1. Удаление файла старой базы данных (Рекомендуемый)
Так как мы еще не изучали механизм миграций, проще всего «сбросить» базу данных:
1. **Остановите** запущенный проект в вашей среде разработки (Rider / VS Code).
2. Откройте проводник вашего проекта и **вручную удалите файл `students.db`** (а также файлы `students.db-shm` и `students.db-wal`, если они создались рядом).
3. Запустите проект заново. Метод `EnsureCreated()` увидит, что файла базы нет, создаст его с нуля и сразу добавит туда **и таблицу `Students`, и таблицу `Groups`**.
*Минус:* Все добавленные вами ранее тестовые студенты удалятся.

#### Способ 2. Переключение на базу данных в оперативной памяти (InMemory)
Если вы не хотите возиться с удалением файлов, переключите ваше приложение на работу в оперативной памяти. Для этого зайдите в файл `Program.cs`, закомментируйте строку с `.UseSqlite(...)` и замените её на:

```csharp
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseInMemoryDatabase("StudentsInMemoryDb"));
```
База в оперативной памяти создается с нуля абсолютно при каждом запуске приложения, поэтому таблицы никогда не будут конфликтовать.

На следующем занятии мы разберем работу с миграциями и полностью решим эту проблему.
